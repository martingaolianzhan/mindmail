# DEP-001 dependency risk review

This is a scoped dependency review, not a production-readiness approval. FIX_PLAN.md owns task/release status. Evidence was obtained from the npm registry audit service and installed package/source inspection, not live application services. Audit counts describe affected packages (including propagation), not independent exploits.

## Baseline and decision rules

- Clean worktree at start. Node v24.20.0; npm 11.19.0; declared npm 10.5.0. The latter is available through `npm exec --package=npm@10.5.0`; runtime support policy remains CFG-002, unchanged.
- Baseline audit: exit 1, 79 packages: 5 critical, 36 high, 32 moderate, 6 low. Historical 57 is superseded, not a regression measured against an identical advisory database.
- Baseline `npm ls --depth=0`: exit 0. Full React/KBar peer tree: exit 1 (`ELSPROBLEMS`). Top-level success does not prove peer consistency.
- Dispositions: REMEDIATE/REMOVE when a compatible, targeted change exists; ACCEPT only for demonstrated non-material paths with explicit invalidation/expiry below. Any unresolved materially exploitable path blocks DEP-001 and public deployment.

## Acceptance conditions (apply only to findings retained in final evidence)

All acceptances expire **before public deployment or 2027-01-31, whichever occurs first**, and must be re-evaluated immediately when a compatible upstream fix appears. They are invalid if the described input boundary changes. No acceptance covers untrusted repository contributions being executed with secrets; CI must not grant secrets to untrusted builds.

- **Tiptap core:** accept only while fixed built-in schemas receive string HTML, not untrusted JSON attribute/config objects, third-party extensions, or caller-controlled HTMLAttributes. Adding any such path requires patched core (currently >=3.30.4) or a reviewed boundary before use.
- **AI:** file-type whitelist, HTML diff formatter and AI state patch advisories are accepted only while unused; introducing file messages, uploads, createAI/useAIState or patch APIs invalidates acceptance. Provider JSON response/error buffering is accepted only for the fixed trusted Google endpoint; introducing arbitrary provider URLs or attacker-controlled raw response bodies invalidates it. Ordinary resource limits remain relevant, but this is not permission to accept a demonstrated attacker-controlled unbounded parser path.
- **Build/lint parsers:** accept only for checked-in patterns/CSS/config and local caches. No service may compile arbitrary mailbox/user CSS, source maps, YAML, glob expressions or lint configs. Before enabling a build service or processing untrusted artifacts with secrets, patch/replace or isolate first.
- **Vitest/Vite/tinypool:** accept only for `vitest run` node tests with trusted config, no exposed browser/UI/mock/dev server and no user-derived worker options/prototype pollution. Enabling browser/server modes or executing untrusted tests with privileges invalidates acceptance.

### Peer conflict conclusion

Baseline KBar beta.45 allowed React 18 but pulled react-virtual 2.10.4 with peer React `^16.6.3 || ^17.0.0`; installed React/DOM were and remain 18.3.1. MindMail does use its virtualised command palette, so the relationship could not be dismissed as unused. No baseline runtime defect was reproduced; incompatible metadata alone was not treated as an exploit.

KBar beta.48 still has that relationship. KBar 1.0.0 is the smallest upstream root release found that replaces react-virtual with @tanstack/react-virtual (installed 3.14.22) and supports React/DOM `^17 || ^18 || ^19`. Compared package declarations: KBarResults/onRender/useMatches signatures are unchanged; Action type changes are syntax-only. The real-package Vitest test renders the provider with React 18, verifies section/action/shortcut metadata and executes its callback. Application typecheck and offline production build also pass with unchanged KBar source. This is not an interactive browser keyboard/scroll E2E claim; normal pre-deployment UI verification remains required. Full React tree and complete npm tree now exit 0; react-virtual is absent. No peer suppression flags/overrides or palette rewrite/removal were used.
